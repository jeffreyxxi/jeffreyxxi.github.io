# AI 模型搭配与选型

## 说明

- 信息更新时间：`2026-04-29`
- 本文关注的是“模型怎么搭配做事”，不是单纯比较谁跑分更高
- 目标是服务于个人开发、全栈成长、自动化实践

## 当前主流模型搭配建议

### 第一梯队：主力模型

- `GPT-5.4`
  - 适合全局推理、复杂编码、长任务、工具调用、电脑操作
- `Claude Sonnet 4`
  - 适合稳健编码、代码解释、工程理解、重构和排错
- `Claude Opus 4.1`
  - 适合更重的分析、推理和长链任务
- `Gemini 2.5 Pro / 3.1 Pro`
  - 适合超长上下文、多资料归纳、跨文档理解

### 第二梯队：开放模型 / 性价比模型

- `Qwen3 Coder`
- `Devstral`
- `Kimi K2`
- `gpt-oss`
- `DeepSeek` 相关编码与推理模型

它们更适合：

- 成本敏感的实验
- 开放栈工作流
- 本地 / 自托管 / 多 Provider 场景

## 结合你的背景，我建议的三层组合

### 方案 A：当前最稳的主力组合

- 主力编码：`Codex + GPT-5.4`
- IDE 协作：`Cursor`
- 自动化层：`OpenClaw`

适合：

- 想优先把项目做出来
- 想在真实任务里顺带补全栈能力

### 方案 B：更偏工程能力成长

- 主力编码：`Claude Code + Claude Sonnet 4`
- IDE 协作：`Cursor` 或 `Copilot`
- 开放学习：`Aider` 或 `Continue`

适合：

- 想强化终端、部署、日志、后端和排障能力

### 方案 C：更偏研究 Agent 本身

- 主力学习栈：`Cline / OpenCode / Continue`
- 对照主力模型：`GPT-5.4`、`Claude`、`Gemini`
- 自动化层：`OpenClaw`

适合：

- 想真正理解上下文工程、权限、MCP、工具编排、多模型分工

## 如果目标是独立完成小项目全生命周期，需要补的 AI 能力

- 任务拆解：把模糊需求拆成可执行子任务
- 上下文工程：知道什么时候给上下文，什么时候收敛上下文
- 验证闭环：让 Agent 写完后自己测试、看日志、回归验证
- 工具编排：会用 MCP、CLI、Webhook、Cron、Browser automation
- 规则沉淀：把高频经验写进 `AGENTS.md`、Skill、脚本和模板
- 多 Agent 协作：学会让不同 Agent 分工而不是重复劳动
- 成本意识：按任务选模型，而不是所有事都用最贵模型

## 当前阶段性判断

截至 `2026-04-29`，如果目标是“前端工程师逐步独立完成完整小项目”，我的阶段性判断是：

1. 主力先用 `Codex + GPT-5.4`
2. IDE 侧保留 `Cursor` 作为高频协作工具
3. 再补一套开放学习栈，优先从 `Cline / OpenCode / Continue` 中选
4. 如果要把 AI 从编码扩展到持续帮我做事，就要开始认真搭自动化层
